# 点击死区与有效命中区：桌面和移动端

视频要点（由用户补充）：检查用户以为可点的范围和实际响应点击的范围，找出点击死区。桌面鼠标、触控板和移动触屏都适用；下面的诊断与尺寸建议是本 Skill 的工程整理，不把具体数值归于视频。

## 先画清交互边界

- 列出每个控件的**视觉范围**、**真实命中范围**和预期动作。整行、整卡或图标周围的空白是否可点，取决于它是否在视觉上被表达为同一个控件；普通留白不应为了消灭“死区”而误触相邻操作。
- 视觉上同属一个按钮的文字、图标、内边距和圆角内部应触发同一动作。不要让只有文字节点可点、按钮底部一条区域无响应，或把可点击层缩在视觉背景内。
- 相邻的删除、展开、选择等动作必须有独立命中范围；扩大目标时检查范围是否重叠，避免点 A 却执行 B。悬停、按下和选中反馈应与真实命中区一致。

## 桌面端：鼠标与触控板

- 沿视觉边界、留白和相邻控件间隙移动并点击，确认悬停提示、`cursor`、焦点及实际点击动作一致。鼠标可以精确指向小范围，因此边缘几像素的死区和错误 hover 尤其容易暴露。
- 检查文本节点与背景容器是否只有一部分绑定事件；检查覆盖层、伪元素、滚动条附近和拖拽手柄是否截获点击。不要用覆盖整块内容的透明按钮补死区，这会遮住内部操作和文本选择。
- 可点击卡片内部若含链接、菜单、删除等独立动作，要分别检查空白区与子控件；拖选文本、双击、拖拽不应意外触发父级动作。

## 移动端：尺寸与手势

- Web 指针输入至少核对 [WCAG 2.2 目标尺寸（最低）](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)：通常为 24 × 24 CSS px，标准列有间距等例外，也适用于桌面鼠标。面向手指操作时优先留更宽裕的尺寸和间隔；[Apple 平台设计建议](https://developer.apple.com/design/tips/)的触控目标为至少 44 × 44 pt，点与 CSS px 是不同单位，不能直接混写成同一个强制标准。
- 可扩大按钮自身 padding 或命中范围，同时保持图标视觉尺寸；不要用覆盖其他控件的透明层来补面积。靠近屏幕边缘、底部安全区、软键盘和浮层的目标也要可达。
- 在可滚动列表中验证轻点、慢速滑动和惯性滚动：滑动不应误触打开/删除。不要对整页设 `touch-action:none` 来掩盖手势冲突；需要拖拽时只对对应区域约束手势。
- `hover` 不是触屏上的可靠反馈或说明入口。关键状态和受限原因需要触摸与键盘可达的表达。

## 移动端：震动反馈

- 触觉反馈应对应清楚的离散事件，例如选择已生效、拖拽吸附或重要操作完成；与视觉状态同时发生。不要让每次普通点击、滚动或无效操作都震动，也不要靠震动表示控件“已经可点”。
- 优先使用平台已有的触觉模式，避免强烈、连续或语义混乱的自定义震动。让用户能关闭反馈，并确保关闭或设备不支持时，视觉/文字反馈仍完整。[Apple 的触觉反馈指南](https://developer.apple.com/design/human-interface-guidelines/playing-haptics)明确建议克制使用并提供关闭方式。
- Web 的 `navigator.vibrate()` [支持范围有限](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate)，且需要用户激活；按能力检测后调用，失败时静默降级。原生移动应用应使用平台触觉 API，不把 Web API 当作跨端保证。

## 定位死区与误触

1. 在桌面实际窗口、窄视口、不同缩放和触屏设备上，依次点击视觉范围的中央、四角、边缘和控件间隙；记录期望动作与实际动作。
2. 用 DevTools 检查命中元素和盒模型（`elementFromPoint()`、`getBoundingClientRect()`），对照 padding、伪元素、`z-index`、裁切、transform 和覆盖层。`pointer-events:none` 会使事件穿透到下层，不能不分区域地套用。
3. 修正目标元素的布局/语义与事件归属，再检查触摸、鼠标、键盘和屏幕阅读器路径。若父级与子级都可交互，保证子动作不会同时触发父动作。

验收标准：视觉上可点的区域响应一致；非交互留白不会产生意外动作；相邻目标没有重叠误触；桌面 hover 与点击范围一致，触屏滚动与轻点可区分；触觉反馈可关闭、可降级，焦点与视觉反馈始终清晰。

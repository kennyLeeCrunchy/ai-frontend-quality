# 用户内容与富文本安全渲染

展示用户输入、Markdown、粘贴的 HTML、模型输出或外部嵌入内容时阅读。

## 渲染约定

- 普通文本使用框架的转义输出。按功能决定是否允许 HTML，复用项目现有的渲染与净化方案。
- 允许 HTML 时，使用维护中的净化器和明确的标签、属性及 URL 协议策略。净化后的内容再经插件改写时，复核最终输出路径。
- Markdown 的原始 HTML、代码高亮插件、图片和链接也遵循相同策略。流式展示的中间片段与最终渲染都应经过安全路径。
- 链接和媒体 URL 根据用途校验协议与来源。相对地址按项目路由处理，跳转行为和下载入口保持明确。
- 嵌入网页或可执行预览按来源与功能选择隔离机制。例如 iframe 使用最小化的 sandbox 权限，跨窗口消息校验来源和结构。

## 前后端职责

| 位置 | 程序应执行的控制 |
|---|---|
| 服务端 | 校验写入与读取权限，执行所需的数据校验及存储策略。 |
| 渲染端 | 根据最终 HTML、属性和 URL 上下文转义或净化，再写入对应位置。 |
| 预览与嵌入容器 | 使用来源限制、隔离策略与必要的安全响应头。 |

界面提示和模型语义判断属于软约束。渲染安全依赖实际执行的转义、净化、协议校验与隔离代码。服务端和渲染端按各自处理的内容实施对应控制。

## 验收

覆盖带事件属性的 HTML、危险链接协议、Markdown 原始 HTML、恶意粘贴、流式中间片段和非预期来源的嵌入消息。同时检查正常代码块、合法链接、复制与文本选择仍可用。

参考 [OWASP XSS 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)。

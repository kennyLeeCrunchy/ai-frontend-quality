# 移动端：触控、手势与动效

涉及手机或平板的触屏交互时，按需读取相关小节。通用的点击死区和事件归属见 [点击目标与死区](pointer-hit-targets.md)。

## 触控尺寸与手势

- 触控目标需要给手指留足尺寸和间距。[Apple 平台设计建议](https://developer.apple.com/design/tips/)的触控目标为至少 44 × 44 pt。移动 Web 使用 CSS px，按 [通用点击目标规则](pointer-hit-targets.md#先画清交互边界) 核对 Web 标准，再根据实机触屏体验留足空间。
- 可扩大按钮自身 padding 或命中范围，同时保持图标视觉尺寸；不要用覆盖其他控件的透明层来补面积。靠近屏幕边缘、底部安全区、软键盘和浮层的目标也要可达。
- 在可滚动列表中验证轻点、慢速滑动和惯性滚动：滑动不应误触打开/删除。不要对整页设 `touch-action:none` 来掩盖手势冲突；需要拖拽时只对对应区域约束手势。
- `hover` 不是触屏上的可靠反馈或说明入口。关键状态和受限原因需要触摸与键盘可达的表达。

## 移动端面板与动作菜单

- Bottom Sheet 用于从底部呈现内容或短任务。检查内部滚动、下拉关闭、底部安全区和软键盘，确保输入与主要操作在实际视口内可达。
- Action Sheet 用于让用户选择当前对象的相关动作。内容面板仍按内容和任务选型。需要防误关、确认或撤销时，参照 [通用组件选型](requirements-and-component-choice.md)。
- 重要手势提供可见的替代入口，例如可滑动关闭的面板也提供关闭按钮。

## 触觉反馈

- 触觉反馈应对应清楚的离散事件，例如选择已生效、拖拽吸附或重要操作完成；与视觉状态同时发生。不要让每次普通点击、滚动或无效操作都震动，也不要靠震动表示控件“已经可点”。
- 优先使用平台已有的触觉模式，避免强烈、连续或语义混乱的自定义震动。让用户能关闭反馈，并确保关闭或设备不支持时，视觉/文字反馈仍完整。[Apple 的触觉反馈指南](https://developer.apple.com/design/human-interface-guidelines/playing-haptics)明确建议克制使用并提供关闭方式。
- Web 的 `navigator.vibrate()` [支持范围有限](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate)，且需要用户激活；按能力检测后调用，失败时静默降级。原生移动应用应使用平台触觉 API，不把 Web API 当作跨端保证。

## 手势驱动的弹簧动效

- 拖拽面板、滑动收起和边缘回弹等与手指运动直接相关的交互，拖动时跟随手势。松手后，以当前位置和释放速度为起点，由弹簧模型向目标收敛。吸附目标可结合位置和速度判断。
- 弹簧运动要能被打断和改向。用户重新按住或反向操作时，从当下状态继续响应。使用平台或项目已有的弹簧能力，让初始速度、响应和阻尼决定运动，避免用固定参数的贝塞尔曲线和预设时长模拟这类手势回弹。
- 从平稳收敛开始。普通点击通常不需要过冲，甩动有明显动量时可按用途和用户偏好保留少量回弹。参数通过真实设备调节。尊重系统的「减少动态效果」偏好，可改用短淡入或直接切换，保留同样的状态和操作。
- 实机验收慢拖、快速甩动、中途重新抓住、反向和取消。检查有没有跳帧式位移、等待动效结束才可再次操作，或与列表滚动争抢手势。

参考 [Apple WWDC18 · Designing Fluid Interfaces 的弹簧讲解](https://developer.apple.com/videos/play/wwdc2018/803/?time=1916)、[手势动量与落点](https://developer.apple.com/videos/play/wwdc2018/803/?time=2763) 与 [Apple HIG · Motion](https://developer.apple.com/design/human-interface-guidelines/motion)。

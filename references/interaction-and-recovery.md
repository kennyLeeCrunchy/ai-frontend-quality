# 操作反馈、命中区与恢复

用于卡片/工作区选择、临时不可操作的控件，以及忙碌期间上传或导入等操作。先复用产品既有组件和状态语义，再做最小范围调整。

## 暂不可操作的按钮

- 说明具体原因和下一步，例如“本轮对话结束后处理”，不要只用 `not-allowed` 光标、灰色按钮或含糊提示。
- 短说明可在鼠标悬停及键盘 `focus-visible` 时淡入；需保证不会被容器裁切、不会遮住关键操作，并给触屏用户提供点击/常驻提示等价路径。提示使用 `aria-describedby` 关联，原因应清楚、可读，不依赖颜色。
- 原生 `disabled` 控件不会进入键盘焦点，也通常无法承载 hover 说明。若产品要求用户能查明禁用原因，可用 `aria-disabled="true"` 保持可聚焦，并在 click/submit/快捷键等所有执行入口硬性拦截；只有真正禁用且不需要解释时才优先使用原生 `disabled`。
- 当解释超过一两句、用户需要采取操作或状态会持续较久时，使用就近的 inline 提示/队列条目，而不是悬浮 Tooltip。hover/focus 动效短而克制；`prefers-reduced-motion` 下减少装饰动画。
- 用户已经触发的操作要显式反馈阶段与结果；不能让“已选择文件”看起来像“已上传/已处理完成”。失败时提供保留内容、重试或移除路径。

## 卡片选择与嵌套操作

- 若整卡代表选择项，整个卡片表面（包括底部和空白区域）都应处于明确且一致的选择命中区，触控目标不应只限于标题或文字；选中态通过边框、背景、勾选或语义属性表达，避免只改变文字颜色。
- 删除、展开/收起、链接、编辑、复选框等嵌套控件各自执行，不冒泡触发卡片选择；点击卡片空白仍能选择/取消。用实际事件目标或独立按钮结构控制冒泡，不用透明遮罩覆盖嵌套控件。
- 选择卡片提供键盘等价操作、可见焦点及 `aria-selected` / `aria-pressed` 等匹配角色的语义。验证 Tab 顺序、Enter/Space 行为和嵌套按钮的独立可达性。

## 加载切换与原子呈现

- 对同一工作区切换的画布、聊天标题和消息等区域，共用同一个目标 ID 与 loading 生命周期；不要在多个组件各自延迟触发 skeleton，形成两次闪屏或短暂串入另一个工作区的数据。
- 旧快照仍对应当前可见工作区时继续显示；切换目标不同且没有其缓存快照时，尽早展示结构贴合的局部 skeleton。关联数据就绪后统一替换；次要数据可以后加载，但要保持一致的工作区归属。
- 对刷新、切换工作区和慢操作分别设计反馈。skeleton 应固定真实布局尺寸且只显示在确实等待的区域；请求快速结束就直接显示结果。淡入淡出可以衔接替换，但不延迟内容可用，也不强行给 skeleton 增加最短等待。
- 调试闪烁时区分请求重复、React remount、skeleton 定时器、过渡重放、缓存失效及状态分属不同组件；用时间线记录 loading、请求完成和 UI commit，而非只靠肉眼猜测。

## 工作区编号一致性

显示名、稳定 ID 与排序编号是不同字段。重命名不应隐式改变稳定身份；列表排序、创建后的下一个编号、刷新后结果应由同一套规范化规则决定。若编号允许释放或稀疏，应明确告知并保持前后端一致；不要让前端本地推算结果看起来跳号而服务端返回另一顺序。
